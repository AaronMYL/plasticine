# Plasticine 视觉协作 Skill

让 Plasticine 成为**安静的阅读与思考空间、精密的个人工作室，以及能够有机变化的共同工作环境**。让内容易读、动作可理解、变化可追踪，而不是靠装饰宣称智能或活力。

## 证据身份与使用边界

- **用户已确认的方向**：上述三种气质并存；结构清晰、阅读舒服、内容可直接操作、细腻地感到共同工作在发生。
- **当前依据**：本次明确指令与确认设计、已定的产品决定和源码。2026-11-05 第 117 条已重做 Harness、退役旧任务 / 关切 / 判断等对象；历史四份重写方案用于理解演变，不覆盖当前决定。2026-11-06 六组设计已确认进入实现，是否已经实现、验收或发布另见本轮记录。
- **视觉例外**：令牌、材质、字体、圆角、字号、壳的宽度与两种收起、页头、浮层与对话栏的关系，以 2026-10-27 定下的方向 I（本 Skill 为准，画布是示意）为准。《UI 方案》里若还留着液态玻璃待定、glass.css 令牌照旧、方向 H 的靛蓝 / 梅紫 / 白卡片、侧栏 240/56px、对话栏 360px 或「收起成一条边」的写法，一律作废，按本 Skill 做，并把这处没同步的地方写出来。
- **已定的视觉方向 I · Absolute（2026-10-27，用户自写规范）**：布局仍取方向 C（分区标题条、表格式的行、紧凑字号、等宽数字、侧栏分组 + 快捷键提示）；颜色只有一个底色和一个前景色（2026-11-05 照 0.2 老版换成暖米：浅 `#FCF9F6` / `#2A2622`，深色暖炭黑 `#2B2826` / `#F5F1EC`）加一个陶土强调色 `#A1674E`（全屏 ≤ 2%，只做点和描边）；状态色四个降饱和；没有卡片、没有阴影、没有渐变、没有玻璃，板块靠 1px 细线和留白分开；字体 Geist Sans + Geist Mono 打包、中文回退苹方 / MiSans / 微软雅黑；圆角只有 4 / 8 / 12 / 正圆，按钮不用胶囊。方向 H（纸色、靛蓝、白卡片、胶囊）整套作废。全套设计稿在 Claude Design 画布《Plasticine 新版界面设计》：https://claude.ai/artifact/5WTXgdmK9fc9wTL1dD5eBo （画面里的数字是示例）。
- **产品已明确的语义**：消息统一承接自己的 Plasticine、联系人、群和邮件；主对话与后台线使用同一 Harness；记忆按主题文档组织，项目包含待办与档案。原话、引文、推断和执行结果保留真实来源。不要恢复三栏记忆、独立判断页或旧任务看板。
- **本 Skill 的设计提案**：参考里标「提案」的参数、布局策略和组件方案是可校准起点，不是用户已经批准的设计稿；标「方向 I」「已定」的是定稿内容。
- 创建或阅读本 Skill，不等于允许安装、改代码、增加依赖、改变业务语义或部署。以当前任务授权为准。讨论请求只输出设计建议；明确实施请求才进入实现，同时遵守 plasticine-code 与 `docs/dev-workflow.md`。旧内置 self-iteration 已退役，不再作为工作前提。
- 本稿独立编写，仅借鉴按交互意图选择机制、按需读取组件规范的组织方法，不引入 ui-motion-guide 的代码、样式、资产或运行依赖。

## 先确定这一次在做什么

| 当前请求 | 应做的工作 | 不应声称 |
|---|---|---|
| 讨论方向、评审截图 | 识别问题、提出取舍、列出尚待决定处 | 已修改应用或完成真实行为验收 |
| 制作原型或设计稿 | 在授权的独立产物中表达方案，标明模拟状态 | 模拟进度是实际任务进度 |
| 修改应用 | 先读取相关页面、组件、状态与现有设计约定，再做范围内改动 | 未检查的技术栈、布局、状态已经存在 |

不要仅凭旧截图认定当前 DOM、框架或版本。无法读取实现时，可以完成概念方案，把相关假设明确列出，不虚构代码事实。

## 核心决策顺序

1. **当前意图**：用户正在阅读、比较、编辑、决定、等待还是恢复现场？这一刻什么最重要？
2. **信息身份**：这是原话、观察、判断、约定、执行状态还是来源？什么已确定，什么只是提议？
3. **稳定部分**：阅读位置、焦点、草稿、选择和对象身份，哪些不能因更新丢失？
4. **必要变化**：是否真的需要动效？若不动也能更清楚，就保持静止。
5. **最小机制**：用空间、文字、颜色、形状或短过渡表达变化，不同时叠加所有通道。
6. **证据核验**：按当前产物检查实际行为。代码静态检查、原型试玩、真实应用验收分别报告。

出现冲突时，优先保住真实语义、可操作性和阅读稳定，再调节装饰。不要为了"安静"藏掉错误或待决事项；不要为了"精密"把全部数据挤满屏幕；不要为了"有机"让内容持续漂动。

## 复用当前组件

优先复用消息、要你定卡、工作行、结果链接、就地编辑和浮层 / 抽屉，以及当前的联系人、项目和主题文档组件。对话容器与侧栏是壳。具体行为和验收句见 references/component-recipes.md；旧“七个原语”中的退役业务不再是必须创建的组件清单。

- 优先组合现有组件并使用方向 I 的既有令牌。确需扩展组件或令牌时，说明现有方案不能满足的行为；涉及尚未明确的个人偏好时具体询问。
- 先确定用户对象、当前状态和主操作，再选择组件。不要仅因旧配方存在就创建已退役功能。

## 方向 I 的硬规矩（已定 2026-10-27，覆盖本 Skill 原稿里与之冲突的说法）

1. **一个底色、一个前景色，没有卡片、没有阴影**：整页 `--bg`，板块靠 1px `--line` 和留白分开；不用 `backdrop-filter`、半透明面板、渐变、白卡片、外框。唯一的阴影 `--lift` 只给浮起物（Sheet、浮动圆球、抽屉、弹出菜单），遮罩只用 `--scrim`。
2. **不放插画，不用渐变装饰**：没有真插画就留白，不画占位团块、不用渐变底。
3. **字体**：Geist Sans + Geist Mono 打包进应用（本地文件，只打英文字体，不从网上加载）；中文回退苹方 → MiSans → 微软雅黑。数字用等宽数字（`tabular-nums`）；独立的数字、金额、计数、快捷键用 `--mono`。夹中文的来源、时间、w、系统状态整行用 `--sans` + `tabular-nums`（共用 `text-meta` 类），不用等宽字体，避免 Windows 中文回退宋体（第 92 条）。中文不拉字距、不大写；字重只用 400 / 500 / 600。
4. **颜色只用令牌表**：唯一强调色是陶土橙 `--accent`，全站只表示「等你」（等你的点、要你授权 / 要你动手的图标块描边、圆球角标、试跑细条纹），不做文字、不做按钮底；第 104 条起可用 `--hue-*` 给类别和项目上色（只染图标、圆点和同色淡底）；主按钮是 `--fg` 实底 `--bg` 字；当前位置 `--tint2` 底；状态色 `--run` / `--ok` / `--err` 只染符号，只有出错可以写字；「Plasticine 写的、推断的、提议的、推荐的」用 ✦（`AiMark`），成段的再加左侧 1px `--fg3` 细线，不用颜色，界面里没有紫色。不现写 rgba 颜色和阴影。
5. **字号、圆角、间距从令牌表起**：页面标题 24/32·600，区块标题和回复结论 15/24·600，正文 14/22，笔记长文 16/28，说明 12/18，小签 11/16·500，数字 22/28·500；最小字 11。圆角只有 4 / 8 / 12 / 正圆，按钮和标签不用胶囊。间距只用 4 / 8 / 12 / 16 / 24 / 32 / 48。
6. **壳与对话容器**（11-07 两层侧栏、11-08 第二栏可收起）：电脑上最左一条 72 宽图标栏，三组入口——现在 · Plasticine ·
   消息 · 任务 ｜ 网页 · 信息流 ｜ 笔记 · 资料库（组间只留空隙），底部 ⌘K、新建、头像（设置）；点一个入口第二栏（252 宽）
   换成这个栏目的列表（「现在」没有第二栏），主区只放当前打开的那一个东西。只有网页是标签（竖排在网页栏目的第二栏：置顶、
   分组、今天，标签画网站自己的图标），Plasticine 自己的页面是导航、前进后退走地址；⌘K 全局切换。第二栏标题行最右边能收起
   （⌘\，按栏目各记各的）：网页收成 56 宽窄栏（只剩网站图标），别的栏目整列让给主区、展开按钮在主区页头最左边。
   手机：当前页全屏 + 底栏 现在 · Plasticine · 消息 · 笔记 · 更多（任务、信息流、图书、空间在「更多」抽屉里）。
   对话：右下角浮动对话框跟着当前页，收起是圆球；Plasticine 栏目本身就是对话。主对话的整页、展开容器和浮窗共用同一线、
   草稿与阅读状态，不另造第二份记录。实际宽度与断点从当前 shell 读取，见 references/views.md。
7. **浮层不挡对话**：电脑上 Sheet 浮在主区里（上右下各留 16，宽 560，圆角 12，`--lift`），遮罩只盖主区，对话栏照常可用。细节见 references/component-recipes.md「浮层 / 抽屉」。
8. **画布是示意，规则在这里**：画布里的数字是示例；画布某处的像素细节和本 Skill 的规则对不上时，按本 Skill 做，并把这处不一致写出来。

## 让布局自己说话（2026-11-03《全量界面优化》，用户定；2026-11-04 重做悬停时补充）

用户原则：**避免不必要的次要标签和描述，让布局自己说话；用非文字的视觉（布局、结构、颜色、图形、图标、动画、交互）传达信息量。**

用户 2026-11-04 给的工作原则（原样）：

- 前端质感与丝滑动效是核心要求。涉及前端的改动，可以通过多轮截图验收持续打磨。
- 代码开发不重复造轮子，建议参考对应成熟项目的源代码。
- 不做过度开发，以优雅为原则，以用户体验为第一性原理。
- 避免不必要的次要标签、说明文字、辅助文案、描述性文字和冗余微文案，让布局、视觉层级、间距和清晰的主操作自己完成解释。
- 优先使用强视觉层级和自解释的结构，而不是依赖文字解释。默认不添加口号式文案、教学段落，也不在每个区块下添加「帮助说明」。确需补充信息时，优先使用 info 图标搭配 tooltip，而不是始终显示次要文字。
- 保留必要的表单标签和可访问名称，不能为了界面清爽而牺牲可访问性。
- 危险或不可逆操作（如删除、支付、提交永久性变更）必须保留清晰的后果提示。
- 去掉说明文字后，首次使用的用户仍应能看懂：下一步点哪里，点击后会发生什么。
- 重写已有界面时，先去掉冗余标签和说明；如果清晰度下降，再优化布局和按钮文案。

取值规则（接 10-20《界面信息取值》）：

1. 一样东西只说一次：图标说了类别，就不再写类别字；行首行尾不写同一件事。
2. 署名、状态、权重、进度用符号；只有出错和做了收不回的后果写字。
3. 零、空、默认值不显示（「0 在做」「无截止」「还没有节点」「健康度未定」）；空的小节整节不出现，整页空才写一句。
4. 机制和排序规则不进界面（「不参与排序」「按紧急、相关…排」「主会话是总调度」「每行链回原话」）；顺序就是排序。
5. 每样说明先归三类（2026-11-04 重做悬停）：**必要**的常显、放进正常层级（时间、状态、出错原因、对方是谁、关键数字、
   做了收不回或要花钱的后果；一行放不下就在标题下面一行 12/18 `--fg2` 小字，或改按钮文案让它自解释）；**补充**的放进
   ⓘ（`InfoTip`，`client/src/shell/info-tip.tsx`：16px 描边 info 图标，`--fg2`、悬停 `--fg`，跟在要补充的那个东西
   后面——标题后、数值旁，不是整行）；**冗余**的删掉。没有「悬停才显示」，不许整行 / 整卡的浮框。
   悬停提示只挂在 ⓘ 和图标按钮这类小元素上：写 `data-tip="…"`（可选 `data-tip-side`，也可写在工具条容器上），或用
   `<Tooltip content>`；`IconButton` 的名字自动进提示（像浏览器工具栏，不算冗余），不用系统 `title`。全应用一个
   `TooltipLayer`（`client/src/shell/tooltip.tsx`，Floating UI 定位）：锚在元素上，悬停约 500ms 出、移开立即收，
   相邻之间瞬切；键盘 `:focus-visible` 出；触屏点 ⓘ 出、点别处收；自动翻边 / 贴边；`role="tooltip"`、开着时
   `aria-describedby`。样式 `--fg` 底 `--bg` 字、12/18·500、padding 4 8、圆角 4、无阴影；从所在一侧 3px 外淡入滑进，
   `--motion-fast`，收起更快，减少动态效果时只淡入淡出。
   一行的次要操作收进行尾 ⋯（`RevealMore`，点了出菜单）；一列里有的行没有次要操作时留同宽占位，⋯ 列对齐。
6. 页头不写副标题，数进分段控件的 `.seg-count`；原副标题只在标题悬停里（`PageHeader` 的 `meta` 已改成 `title`）。
7. 遮字测试：把 ≤ 12px 的字全遮掉，页面照样能用、意思不丢，那些字就该删。度量是「次要字占比」（主区里 ≤ 12px、
   不在按钮和输入里的可见字 / 主区可见总字数），目标每页 ≤ 20%。

文字只留给：标题、用户原话、Plasticine 的一句结论、出错原因、做了收不回的后果。

符号词汇表（`client/src/shell/glyph.tsx`，每个符号都有读屏文字和悬停提示 `data-tip`）：

| 符号 | 组件 / 类 | 意思 |
|---|---|---|
| 陶土橙实心点 | `StatusGlyph status="wait"` | 等你（全站只这一个意思） |
| 状态色点，慢慢一明一暗 | `StatusGlyph status="run"` | 在做（减少动态效果时静止） |
| 空心圈 | `StatusGlyph status="idle"` | 没开始 |
| 勾 / 两竖 / 叉 | `done` / `pause` / `err` | 做完 / 暂停 / 出错（出错旁边写一句原因） |

（`aria-label`、`sr-only`、ⓘ 的 `aria-description`），测试按读屏名字和 `data-tip` 查。

## 提案和交付应让人看懂

简短说明：现象与依据 → 设计意图 → 保持不变的内容 → 建议变化 → 未定项或验证结果。

涉及动效时，说明触发条件、起止状态、打断/反向行为、减少动态效果替代方式。涉及参数时，标明是沿用方向 I 令牌、提出新默认，还是经实测修订。

如果一个改动会同时影响交互逻辑和外观，拆开说明。例如"添加保存状态反馈"不自动允许改变保存策略，"增加撤销提示"不代表服务端已经支持撤销。

实现完成后列出真正修改和验证的范围、保留问题与未做事项，不把视觉 Skill 的覆盖范围说成产品已全部具备的能力。
