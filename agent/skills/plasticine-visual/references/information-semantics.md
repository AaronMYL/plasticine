# 信息语义：保持来源与执行状态真实

## 内容身份

| 内容 | 应让用户知道 | 避免的混淆 |
|---|---|---|
| 用户原话 | 谁在什么时候亲自说了什么，怎样返回上下文 | 将委派摘要、外部引文或工具包装文字冒充用户原话 |
| 联系人、群与邮件 | 实际作者、会话归属、是否由 AI 代说 | 将对方的 AI 或网络输入当成本人确认 |
| 主题记忆 | 当前内容、来源、版本，是否是推断或待确认 | 将模型整理的语句升级为本人已确认事实 |
| 项目与待办 | 目标、当前工作和相关资料 | 把活动数量等同成果质量 |
| 执行过程 | 真正发生的调用、等待和错误 | 虚构思考、步骤、进度或回执 |
| 成果 | 完整内容、对应工作和版本 | 把最后一段续写、旧稿或按钮动画当作新交付 |

身份通过结构、位置、必要标签与来源入口表达，不用颜色暗示真假。内容缺少来源时如实保留缺口；引用图标本身不证明已核实。

## 用户来源的判定

消息角色不等于作者身份。当前共享输入来源区分 `user`、`delegation`、`trigger`、`network`、`system`、`unknown`。只有经过核验的本人输入才能标成本人表述；问题卡的文字回答也须核对卡、所属线、调用和作答设备。纯点击模型给的选项不能冒充逐字输入。

引用材料与本人这句话分别保存。未知历史来源不补猜；真实引用存在时可链回，来源已经缺失时不生成假链接。用户的确认、否定和编辑按现有签名 / 版本机制处理，不让模型替用户补答案。

仍保留的来源权重只表达出处，不是真值或权限；不因旧字段存在就在新界面恢复权重仪表盘、判断页或三栏记忆。

## 执行与业务交付分开

| 状态 | 呈现含义 | 可用后续 |
|---|---|---|
| queued | 排队，尚未占用执行名额 | 查看待处理输入；可撤回适用输入 |
| running | 正在执行 | 最近真实进展、补充、暂停 |
| waiting | 等待条件或本人决定 | 打开实际要处理的卡 |
| paused + user | 本人暂停 | 保留原线，明确继续才恢复 |
| paused + quota | 额度限制 | 按实际恢复时间提示，不伪装本人暂停 |
| paused + output_limit | 本次输出未完 | 保留已有正文，继续生成 |
| failed | 执行失败 | 原因与适用重试 |
| idle | 当前没有执行 | 结合队列与结果判断，不能直接显示“已完成” |
| outcome=done | 本轮模型正常结束且没有待处理输入 | 可展示本轮结果，质量与目标达成仍由用户判断 |

联系人任务的接手、交付、收到、退回是独立业务状态。暂停不改负责人；本人接手不只是关掉一个动画。退回后仍保存上一版与意见，排队的新要求未处理时不再次交付旧答案。

超时不必然代表失败；可能已发生的外部操作应进入核实路径。进度百分比必须有实际分母；未知时用阶段或不定进度。动作回执、模型正常结束、业务交付和用户验收分别记录。

## 待决与错误

需要本人决定时明确对象、选项和后果，已有授权在条件不变时不反复询问。一般进度就地呈现；错误与待决不能只留在控制台或自动消失的 Toast 中。危险或不可逆操作保留后果提示与现有确认机制。

“已读”“已处理”“已确认”“已完成”不能互换。读不到数据时显示可恢复错误，不显示为零项或空白成功。服务端结果未返回时不提前显示配对、保存或发布成功。

## 连续性

保持对象身份、原话、草稿、版本与返回位置。主对话的各容器共享一条线；工作详情和对象阅读页可以打开来源，再回到同一处。新数据与流式更新不能把正在读旧内容的人拉到底部；减少动态效果时所有状态仍清楚可用。
