# 组件方案：先行为，再外观

各节是按任务选择的设计配方，不是声明产品已实现这些功能，也不是必须一次完成的组件清单。通用配方与当前业务组件共同使用；历史七原语不再是恢复退役业务的清单。

## 聊天与输入区

**意图**：既可持续沟通，又不打断当前阅读或工作。

- 展开/收起保持输入草稿、附件与选区所需状态，不把面板关闭等同取消任务。
- 最新消息到达时，仅在用户本来追随底部且未选择旧文本的情况下考虑保持跟随；否则稳定阅读位置，显示低干扰的新消息入口。
- 不用整个气泡的强弹跳来表达"回应"。流式文本的布局稳定优先于逐字模糊或打字装饰。
- 发送中、发送失败、等待确认、任务执行中是不同状态；失败保留草稿并给出明确的重试条件。
- 输入区不能挡住最后一段内容和重要操作；窄窗口、软键盘和长草稿下仍能找到发送/停止等当前适用动作。
- 输入、滚动与选中文本不应触发意外关闭。Esc 的含义依当前层级处理，不绕过未保存内容保护。

**验收**：读旧消息时新增消息不抢滚动；收起再展开草稿不丢；失败仍能编辑；长消息/附件/窄屏下无关键控件遮挡。

## 卡片、来源与详情展开

**意图**：让摘要和证据保持关系，减少跳转成本。

- 同一对象保持标题或可辨认锚点。详情可以就地、浮层或整页呈现，按内容长度和比较需要选择。
- 用自然内容尺寸和响应式约束，不照搬固定展开宽高。
- 展开后无需再次播放整篇文字的入场；已有正文保持清楚。
- 初始焦点按展开方式决定：就地展开通常保留触发器焦点；模态按其任务把焦点移入；独立页面通过清楚标题与适用的焦点/播报提示建立新上下文，避免无理由抢焦点。
- 关闭后焦点回到仍存在的原入口；入口已不存在时选择合理的邻近位置，而不是页面顶部。
- 异步加载、无来源、加载失败分开呈现；缺失不伪装成空白成功。

**验收**：键盘可打开关闭；长来源链接不撑破页面；快速反复展开不会残留遮罩；返回后阅读位置仍合理。

## 原位编辑

**意图**：内容可以直接操作，编辑不造成视觉跳跃。

- 只对适合短编辑的内容使用原位输入，长篇约定仍可采用完整编辑区。
- 阅读态与编辑态尽量保持字体度量、宽度与基线；编辑边界与保存方式要可识别。
- 明确保存是自动、显式提交还是失焦触发，不为外观改造暗中变更现有策略。
- 分开保存服务器已确认值、当前草稿与提交中的值。成功回执或可靠的结果核实证据，才能替换已确认值。
- 明确失败时保留草稿，标明未保存，提供适用的重试或取消；取消回到最近已确认值。超时属于结果未知，不自动视为失败；此时取消本地编辑不表示远端回滚，保留提交中的值与核实状态，取得可靠结果后再协调显示。并发修订要提示冲突，不覆盖他人或较新版本。
- Escape、Enter、多行换行和中文输入法组合态分别处理，不能在选字确认时误提交。

**验收**：失败不丢草稿、不出现假成功；取消恢复确认值；中文输入法可用；焦点位置与布局稳定。

## 列表、筛选与重排

**意图**：看得懂变化，找得到原对象。

- 用对象稳定身份跟踪更新，避免索引变化造成错误的视觉关联。
- 新结果到达时不重播全部列表入场。阅读中排序变化可以先提供"有更新"，不静默把对象搬走。
- 用户主动筛选时明确结果数量和空结果原因；保留适用的选中状态、搜索条件和返回位置。
- 删除或取消可以显示撤销，前提是底层确实支持；不能仅做一个视觉倒计时。
- 不能撤销的高影响动作采用适用的明确确认，不靠动效暗示安全。

**验收**：删中间项后焦点合理；快速筛选不显示过时响应；空、单项、多项、长标题都可用；无误导性撤销。

## 任务反馈与操作按钮

**意图**：知道动作是否发生、现在在哪一步、能否继续。

- 防止重复提交的方式与真实操作一致；必要时禁用提交，但保留停止、返回或修改的适用路径。
- 请求已接收可以立即局部反馈，最终成功必须等待真实证据。
- 预计耗时不明确时采用阶段描述；显示百分比必须有可靠分母。
- 请求返回不明时给出核实路径，不直接诱导再次执行。
- 已完成应允许查看结果；失败应说明可行动信息。不要让一个瞬时绿勾成为唯一结果记录。

**验收**：慢请求、明确失败、未知结果、取消、重复点击都有一致状态；任务继续运行时不会因按钮动画结束而假完成。

## 导航、面板与工作区

**意图**：用户始终知道当前位置，能够返回现场。

- 当前入口、悬停、键盘焦点和已打开对象分别表示。
- 同类对象在导航与内容区使用一致名称；不要为了短标签抹掉来源或内容身份。
- 切换区域保持可恢复的滚动、筛选、草稿；返回时优先恢复原对象/段落及其视口偏移，内容已变化则退到最近仍存在的锚点。是否跨页面持久化依产品能力，不虚构保证。
- 窄屏可将并排面板改为逐层进入，但提供清楚返回路径。
- Plasticine 电脑上的浮层（Sheet）不是模态：不加 `aria-modal`、不锁焦点，打开时焦点移入面板、Tab 能走到对话栏。设置弹框继续沿用现有模态与焦点规则；不要把普通详情升级成阻塞整页的弹窗。

**验收**：键盘路线顺序合理；关闭面板不丢工作；当前导航可辨认；浏览器返回与应用返回不相互冲突。

## 通知与待决事项

**意图**：真正需要注意的事被看见，一般进展不争夺注意力。

- 一般更新在对应工作或消息中呈现；影响当前动作的提示就地显示；需要立即决定时明确对象与后果。
- 错误、待决、已读、已处理有不同语义。不要把关闭 Toast 当作已解决业务事项。
- 相同条件下不重复弹出已对齐的信息；重要后续变化说明增量。
- 提供可用的回到任务或来源入口，不只给抽象"查看详情"。
- 自动消失的提示不能承载唯一的关键信息或唯一操作入口。

**验收**：多个更新不堆叠遮住阅读区；键盘可到达；失败后能重新找到提示；点击入口到正确对象。

# 当前组件的组合

## 消息与回复

用户消息使用既有气泡，Plasticine 回复直接排正文。工具与思考的展开使用当前 `lines` 时间线，不重建旧回复层次或退役分歧块。流式更新保留已显示文字；向上阅读时不抢滚动。正文、引用、附件和后台工作入口各有真实来源。

## 要你定卡

沿用现有 AskCard / LineAskCard 与服务端选项；推荐项优先，键盘与触控都能作答。已答、待答、延后、失败分别呈现。卡与所属任务 / 工作线保持同一身份，未收到真实作答回执不能收成“已确认”。空修改意见的返工只放一份表单，不复制一个额外输入框。

## 工作行与详情

工作行呈现标题、实际状态与适用主操作；点击打开统一详情。详情包含任务要求、可追溯原话、进展、完整结果、历史和继续补充。使用当前 queued / running / waiting / paused / failed / idle 与 outcome，不恢复旧十状态任务引擎。

暂停与本人接手分开。输出未完提供继续生成，模型正常结束不能冒充目标验收。详情关闭后焦点和列表位置恢复；手机使用整页，输入区考虑软键盘和安全区。

## 结果与来源链接

结果指向真实笔记、文件或完整正文，版本与工作关系可回看。读取中、读取失败、来源缺失和已有新版本分别处理。原稿保留；有新修改排队时不得将原稿标作新交付。

来源片在发送前可见、可移除；只有标题时不写“已带正文”。读取失败保留草稿，明确重试或只带标题。打开来源后可回到原对象。

## 项目与主题文档

复用现有项目待办、工作、档案、笔记和主题文档组件。手机只读时保留查看来源、复制链接与在对话里继续；不展示无效编辑按钮。编辑继续保持草稿、版本冲突与原话身份，不因视觉整理改变保存策略。

## Sheet 与设置弹框

Sheet 在电脑主区浮起，默认宽 560，上右下留 16，使用 --lift 与 --scrim；手机整页呈现。关闭后焦点返回原入口，快速开关不残留遮罩；减少动态效果时取消位移。

设置沿用既有弹框与焦点管理。设备邀请、备份、工作详情等按各自真实对象组合，不新增一套通用调度或审批产品。正文不堆“功能说明”，必要操作由布局和明确按钮解释。
