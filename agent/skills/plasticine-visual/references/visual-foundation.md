# 视觉基础：Absolute——只靠排版、留白和内容本身

## 内容主次

页面先回答：我在哪里，正在看什么，接下来能做什么，有什么值得我注意。

- 阅读内容占主要视觉权重；页面工具退到稳定、可发现的位置。
- 每个局部区域区分主操作与辅助操作，不让一排按钮拥有同样强度。复杂工作区可以有多个局部主操作，不强制全页只能有一个；但一块区域里只有一个前景色实底的主按钮。
- 首页先回答“现在处理什么、正在做什么、结果在哪里”：等你、在做、最近结果、接着看。数据、空态和错误分别呈现；不恢复回来四句话或十件事来填满版面。具体按当前已确认设计，见 views.md。
- 长文以连续阅读流为主。卡片用于有独立身份或操作边界的对象（要你定卡、成果卡片），不把每段话装进一张卡。对话是连续记录，不是气泡堆：你的消息是右对齐的 `--bubble` 浅底气泡（圆角 12 12 4 12），它的回复不装气泡，直接排在对话栏上。
- 需要对照时支持并排或固定上下文；窄屏改为可回到原位置的切换，不简单把多栏挤成微缩版。
- 需要次级详情时就地展开或使用浮层 / 抽屉。不要把频繁操作一律藏入菜单，也不要把所有低频动作永远摊开。

## 中文阅读

字体按方向 I（已定，2026-10-27）：`--sans` = "Geist", "PingFang SC", "MiSans", "Microsoft YaHei", system-ui, sans-serif；`--mono` = "Geist Mono", "SF Mono", ui-monospace, Menlo, Consolas, monospace。Geist Sans 和 Geist Mono **打包进应用**（本地 woff2，只打英文字体，不从网上加载）；中文按平台回退：Mac / iOS 苹方，Windows 装了 MiSans 就用它，否则微软雅黑。数字用 `font-variant-numeric: tabular-nums`；独立的数字、金额、计数、快捷键用 `--mono`。夹中文的整行（来源、时间、w、系统状态等）用 `--sans` + `tabular-nums`，共用 `text-meta` 样式类，不新增令牌；不用等宽字体，避免 Windows 上中文回退到宋体（第 92 条）。不用衬线，不把英文展示字体用到中文正文。字体列表末尾分别留 `sans-serif`、`monospace` 兜底：Linux 截图机上列表里的中文字体一个都没有，会落到兜底字体（见 validation.md）。

排版：**中文保持默认字距，不大写**；英文微缩大写标签可用（11px、字距 .06em）。字重只用 400 / 500 / 600。

字号从方向 I 令牌起（见下表），长文按设备与真实内容校准：

| 对象 | 方向 I 起点 | 长文 | 调整依据 |
|---|---|---|---|
| 正文 | 14/22（对话整页里的消息 15/24） | 笔记长文 16/28（行高 1.75）；相对单位实现 | 系统文字缩放、中文长段与实际阅读距离 |
| 长文行宽 | — | 约 32–44 个全角字的视觉宽度 | 并排需求、屏幕空间和内容类型 |
| 页面边距 | 电脑上 24、左右 32；手机 16 | 桌面由阅读列决定 | 可操作区域、长链接、工具栏是否溢出 |
| 间距节奏 | 只用 4 / 8 / 12 / 16 / 24 / 32 / 48 | 板块之间 32，板块内 16，卡内边距 16 | 留白是板块之间的呼吸，不是把一个组件撑大 |

标题、正文、说明文字使用有限层级。辅助文字一律 `--fg2`（前景 68%），不靠更小字号或更低对比度实现"高级感"；`--fg3`（45%）只给禁用和装饰，不放要读的信息。日期与版本号清楚可读，不抢内容权重。

中文、数字和英文混排检查实际效果。长 URL、代码、表格拥有局部滚动或换行策略，不让整个页面横向溢出。选中文本、复制和浏览器搜索保持正常。

## 颜色、材质与形状

品牌色已定（方向 I，2026-11-05 换成 0.2 老版的暖米色）：底色、前景色各一个，强调色陶土 `#A1674E`。不再另提新色板；要加颜色先过「要你确认」。

- 层次只有一层：整页一个底色，板块之间靠 1px `--line` 和留白分开，**没有卡片阴影、没有外框、没有白卡片**。只有浮起物（Sheet、浮动圆球、抽屉、弹出菜单）用 `--lift`，背后用 `--scrim`：电脑上只盖主区，侧栏和对话栏不盖、对话照常可用；手机全宽推上的抽屉才盖全屏。不用玻璃、不用半透明面板、不用渐变。
- 卡中卡（要你定卡、成果卡片、文档卡、对话输入框）：透明底 + `inset 0 0 0 1px var(--line2)`，圆角 12，内边距 16；放在 Sheet 里、手机整页上也一样，不再区分「纸上」「卡上」。
- 对话输入框：圆角 12 描边；发送按钮 32×32 圆角 8 `--fg` 底 `--bg` 图标。
- 按钮：主按钮 = 高 32、padding 0 12、圆角 8、`--fg` 底 `--bg` 字 13/500，一块区域最多一个；次按钮 = 透明底 + `--line2` 描边；文字按钮（展开依据、全部、打开）= `--fg` 加下划线（`text-decoration-color: var(--line2)`、offset 3px）；「问一句」「先不」是 `--fg2` 无下划线；回复下面的「理由」「它做了什么 · n 个动作 · 时长」「引用」是高 28 圆角 8 描边 `--fg2` 字 12。
- 小签（11/16·500，padding 1px 6px，圆角 4，中文不拉字距）：要你授权 / 要你动手 = `--accent` 描边 `--fg` 字；要你定 / 要你确认 / 新 = `--line2` 描边 `--fg` 字；差异待核对、已读这类中性 = `--tint2` 底 `--fg2` 字；「它写的 · 时间」= `--line2` 描边 `--fg2` 字；工作活动：进行 = `--tint2` 底 + 6px `--run` 点，等待 = `--tint2` 底 `--fg2` 字。橙色只给「等你」。
- 状态点 6px（图例 8px）：在做 `--run`、等你 `--accent`、已交付 `--ok`（或 `--ok` 勾）、卡住 / 出错 `--err`、离线 `--fg3`。实心点上的勾用 `--bg`（挖空）。
- 分段控件和筛选：单选的少量切换（页签、视图切换、按性质 / 来源这类单选筛选）用分段控件，`--tint2` 底 padding 2 圆角 8，段高 28 圆角 6，选中段 `--bg` 底 + `--line2` 描边、500 字，未选 `--fg2`；可多选或标签式的筛选用 chip，高 28 圆角 8 描边，选中 `--tint2` 底 `--fg` 500；「已赞」这类开关同 chip。手机上分段放不下时改成横向滚动的 chip。
- 悬停提示框：`--fg` 底 `--bg` 字、12/500、padding 4 8、圆角 4，不加阴影。
- 引用片：`--tint2` 底、圆角 4、`--fg2` 12；左竖线只给「它写的」和「分歧」块（1px `--fg3`）。
- 警示横幅（需要处理的工作、读取失败、就地编辑的版本冲突）：`--tint2` 底、左侧 6px `--accent` 点、字 `--fg`、圆角 8，一页最多一条。
- 约定提议的 diff 不用红绿：删去的用 `--fg2` 加删除线，新增的用 `--fg`。已读、看过不用半透明，改 `--fg2` 字。
- `--fg`、`--fg2`、`--line`：阅读层级，不表示内容可信程度。
- 当前位置 = `--tint2` 底 + `--fg` 500 字，不用强调色；键盘焦点环单独画（2px `--fg` 外偏 2px），不与选中状态混淆。
- `--run` / `--ok` / `--err` / `--accent`：执行状态，只染点和描边，旁边总配一个字；只有「出错」可以用彩色写字。
- 内容身份（原话 / 引文 / 推断 / 成果）用位置、来源入口和必要标签表达，不用颜色编码；不要让"判断"为黄色、"原话"为绿色，造成判断低可信、原话已验证的暗示。「它写的、它提议的」= 左侧 1px `--fg3` 细线 + 「它写的」小签，不用颜色；提议沿用必要的来源说明，不恢复退役分歧块。界面里没有紫色。
- 分区沿用方向 C 的写法：标题条（标题 15/24·600 + 11px `--fg2` 元信息（混排用 `--sans` + `tabular-nums`） + 右侧下划线动作），下面直接接表头或第一行，行之间 1px `--line`、表格式对齐。

圆角只体现对象层级：4 < 8 < 12 < 正圆，同类表面保持一致。不要用不断变形的边框来解释 Plasticine 的名字。

## 不用玻璃，不放插画，不打包中文字体（已定）

液态玻璃不作为设计语言：侧栏、手机标签栏、浮层都是 `--bg` 实底，浮起靠 `--lift`，不用 `backdrop-filter`。没有真插画就留白，不画占位团块，不用渐变底。需要强调的区块用粗一点的标题（600）和留白，不用底色铺满、不用实心强调色。

## 响应式取舍

依据空间、输入方式和任务决定布局，不凭设备标签作一刀切禁令。当前壳、对话容器与对象页的响应式行为见 views.md。

- 悬停只能增强反馈，不能成为唯一发现或触发必要动作的方式。
- 触控可操作区域建议从约 44×44 CSS px 的设计目标开始；密集桌面区域应保留键盘途径和足够间隔，任何缩减都要实测。
- 窄屏保留主要内容、必要状态和关键操作；次要工具可以重组，不丢失能力。
- 浮层输入区要考虑可视区域变小、软键盘、安全区域与内容底部留白。未做真机测试就明确标注。
- 保留浏览器缩放能力。放大文字后，关键按钮不互相覆盖，主要内容仍可读取和操作。
