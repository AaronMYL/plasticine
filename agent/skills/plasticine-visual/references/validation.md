# 验证与交付

## 根据产物诚实验证

- **概念讨论**：验证设计是否覆盖意图、状态与边界；不声称代码或浏览器已通过。
- **独立原型**：标明样例数据、模拟等待和未接真实后端；试玩能说明交互是否清楚，不能证明生产数据安全或任务完成。
- **真实实现**：检查项目现有测试方式，针对改动运行静态/单元检查，并在浏览器中验证真实操作。没有权限或连接时报告缺口，不用截图或静态阅读代替运行证据。

## 实施前最小基线

记录当前页面/组件和受影响行为、已有视觉令牌、重要状态及可用的回退方式。只记录与任务相关内容，不开展无边界全站审计。

确认什么必须保持：业务规则、数据、原话与来源关系、草稿、键盘路径、阅读位置、对话栏的滚动位置。需要修改这些时单独说明，不把它们藏在视觉重构里。

## 浏览器场景（四个尺寸 × 浅色 / 深色；交给他确认的至少有电脑 1440×900 和手机 390×844）

| 尺寸 | 看什么 |
|---|---|
| 1440×900 | 图标栏、第二栏（展开、收起：网页窄栏、其他栏目整列让出）、竖排网页标签、主区与对话容器；详情宽度、阅读列与已确认设计一致 |
| 768 宽 | 核对当前 layout.ts 的侧栏与对话自动收起规则（当前自动收起阈值 1280，手机阈值 768）；浮窗打开后草稿与滚动位置不变，不只测两端截图 |
| 390×844 | 手机五项底栏（现在 · Plasticine · 消息 · 笔记 · 更多）；工作、项目与记忆对象可整页承接，返回位置保留，输入区不遮主要操作 |
| 500×500 | 短窗口：输入框、菜单、要你定卡的按钮不被遮、不溢出 |

再加：增大文字或浏览器缩放，检查阅读与必要操作。深色是固定八张里的四张，重点看对比度（`--fg2` 次要字 ≥ 4.5:1、状态点、描边小签、`--tint2` 选中态看不看得出）。截图只证明某一时刻画面，不证明事件、键盘、滚动或状态恢复；手机视口不称为真机验收。软键盘、触控和设备特有问题未测则明说。

Linux 截图环境先检查中文字体。Geist 两款随应用打包；若没有系统中文字体，为测试环境提供 Noto Sans CJK 等中文回退（不添加产品远程字体），字形、字宽和 Mac / Windows 不同；截图看布局和遮挡，不拿它判断中文字形和换行位置，换行敏感的地方在用户设备上再看一眼。

逐张查看截图时核对：看得到吗 · 位置对不对 · 压没压住 · 字清不清。

## 场景矩阵

按改动选取，不为小改动无条件跑全部项目。

| 风险 | 必测现象 |
|---|---|
| 阅读稳定 | 新数据、顶部插入、展开详情后位置不意外漂移；切视图对话栏滚动位置不变 |
| 内容尺寸 | 中文长段、英文长词、URL、空列表、图片缺失不破坏主布局 |
| 真实状态 | 请求中、成功、明确失败、未知结果不互相伪装；送达 / 执行 / 核实 / 验收四个阶段分开 |
| 编辑 | 草稿保留、取消、失败重试、中文输入法与焦点 |
| 动效 | 快速点击、反向切换、离开页面和减少动态效果 |
| 可操作性 | 全键盘可达、焦点可见、非颜色状态辨认、无 hover 唯一路径 |
| 浮层 | 打开关闭、焦点返回、遮罩清理、窗口变小；遮罩只盖主区，浮层开着时对话栏能输入发送 |
| 响应式 | 不遮主要内容、不丢核心能力、无整页意外横向溢出 |
| 性能 | 操作可立即响应，无持续闲置动画、重排卡顿或卸载后活动 |
| 原语纪律 | 复用当前组件和方向 I 令牌，不因旧七原语清单恢复退役功能；确需扩展时记录设计依据 |
| 方向 I 纪律 | 整页一个底色，没有白卡片、没有卡片阴影、没有外框；阴影只有 `--lift` 且只在浮起物上，遮罩只有 `--scrim`，没有现写的 rgba（用令牌色画的 1–2px 描边环，如 `inset 0 0 0 1px var(--line2)`、`inset 0 0 0 1px var(--accent)`、`0 0 0 2px var(--bg)`，算描边不算阴影）；强调色 `--accent`（陶土 `#A1674E`）只出现在点和描边上、不做字不做按钮底、每张截图里面积 ≤ 2%；主按钮是 `--fg` 实底且一块区域只有一个；没有胶囊按钮（999 只在圆球角标）；圆角只有 4 / 8 / 12 / 正圆；字重只有 400 / 500 / 600；中文没有 letter-spacing；要你定卡的小签按类型描边，对话和任务清单「等你」区同样式；「差异待核对」是 `--tint2` 中性小签；「Plasticine 写的 / 推断的」用 `--fg3` 左细线 + 小签，界面里没有紫色、没有靛蓝；没有玻璃（`backdrop-filter`）、没有插画和渐变底、没有远程字体（Geist 是本地文件）；第二栏展开 / 收起、对话框展开 / 圆球都能用 |

对比度可将普通正文 4.5:1、大字和必要界面边界 3:1 作为设计检查目标；按实际背景、字号和用途检查，而不是仅看颜色名称。此处是验收目标，不代替完整无障碍符合性审计。

## 可观察的验收句

优先写"正在看旧消息时，新增消息不会改变当前可见段落；用户点击新消息入口后才跳到最新"，不要只写"聊天流更自然"。

优先写"保存失败时，未保存草稿仍在、错误可见、已确认文本未被覆盖"，不要只写"支持异常状态"。

优先写"开启减少动态效果后无位移/缩放/循环装饰，状态变化仍可识别"，不要只写"兼容无障碍"。

按本次行为写验收：暂停后新要求保留排队，明确继续才执行；输出未完接写后保留前半段；手机点开项目再返回原搜索位置；正文读取失败后草稿和来源还在；真实配对完成前不显示成功。

## 现有采集与真实验证

沿用仍在使用且可关闭的交互采集；先核对消费者，不为保留旧事件而恢复四句话、分歧或旧度量页面。无真实数据时不造指标。针对本次改动补充必要的可观察验证，不为每个组件另建一套仪表盘。

## 收尾

交付说明应区分：

1. 使用的已确认原则与本次新提出的设计选择。
2. 真正修改的组件、文件或原型范围。
3. 已验证场景与实际环境。
4. 失败项、未测项及其影响。
5. 是否安装、提交、部署；未做就不暗示已做。

发现一个组件规范不适合实际数据或操作时，优先修正该场景及其共享原因，不为每个例外增加全局禁令。用户后续确认的新方向可以修订 Skill，但需要保留"设计方向变化"和"当前实现变化"的区别。
