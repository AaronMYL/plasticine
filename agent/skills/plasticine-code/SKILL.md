# Plasticine 代码规矩

这份 Skill 管“代码怎么写”。先读相关模块的现有代码、schema 和测试；历史方案只用于理解背景，不覆盖第 117 条之后的 Harness 与产品结构。“界面长什么样”看 plasticine-visual 和本次已确认设计。两份 Skill 一起用，谁都不新增授权。

为什么要有这份：1ca0391 的代码是省 token 压着写的——`service.ts` 1552 行、平均每行 123 个字符、最长一行 5874 个字符，`catch {}` 吞掉错误。人读不了，换个模型改就改坏。重写从零开始，这些毛病一条都不带过去。

## 底线四条（已定，违反任何一条检查不过）

1. **行宽 ≤ 120**，一行一个语句。禁止 `setInterval(()=>{try{...}catch{}})` 这种一行写完的压缩写法，禁止链式三元超过一层。
2. **一个文件一个职责**。源码超过 500 行时 lint 会提醒（不算失败），提醒你看看它是不是干了不止一件事：是就按职责拆，不是就留着，不为凑行数硬拆。测试文件不限长度，同一个模块的测试放在一起（第 87 条）。
3. **先写测试再写实现**，agent 和 client 都要有测试；client 没有测试的改动不算完成。测试名用中文写它验证的行为。
4. **接口 schema 两端共享**：agent 的 API、工具参数、事件用 typebox 定义在 `shared/`，client 从同一处导入类型；不在 client 里手写一份接口类型。

## 代码长什么样

- 标识符英文、界面文案中文、注释说"为什么"不说"是什么"。文件名 kebab-case，类型 PascalCase，函数 camelCase，常量 UPPER_SNAKE。
- 不吞错误：`catch` 里要么处理、要么带上下文抛出、要么写日志并让状态变成「结果待核实」。空的 `catch {}` 不许出现。
- 用户看得到的错误文案是中文的一句话加下一步（"连接超时，尚未取得服务回执。稍后在对话里看结果。"），不是堆栈。
- 没有魔法数：时限、上限、尺寸进常量并写来由（"默认 4 小时，《UI 方案》§16"）。
- 不写 `any`；外部输入（请求体、模型输出、文件内容）进来先过 schema 校验再用。
- 时间一律 ISO 字符串存、按用户时区显示；金额用整数分；id 用稳定字符串，不用数组下标当身份。
- 异步：每个长任务可取消（AbortSignal）；定时器和订阅有对应的清理；进程退出前保存接续点。
- 不引新依赖，除非写明替代方案为什么不行；不引远程字体（Geist Sans / Mono 的 woff2 随 client 打包，是资源不是依赖）、不引 UI 组件库、不引 Tailwind（前端已定 React + Vite + 普通 CSS + 令牌变量，TipTap 只给笔记）。
- 模型接入用上游 pi（2026-11-05 Harness 重做）：内核依赖 `@earendil-works/pi-ai` 和 `@earendil-works/pi-agent-core` 1.5.x，
  版本号写死、不 fork、不改它的源码，要的行为在 `kernel/`、`lines/` 外面包；升级 pi 是一次单独的改动，跑全测。
  所有模型调用都经内核：主对话和后台活走线（`lines/`），翻译、笔记助手、记忆整理这类旁路调用走 `kernel/` 的
  `TextModels`，不另写 provider、不另存模型设置；不经 Vercel AI Gateway。

## 目录与边界

云端 agent 按当前内核与业务模块分目录，界面优先复用现有 primitives、shell、state 与 views，文件职责见 [structure.md](references/structure.md)。不为遵守旧八模块或七原语清单而恢复已退役目录。三条边界：

- 模块之间只通过各自 `index.ts` 导出的接口往来，不跨目录 import 内部文件。
- 共同状态服务是唯一写 SQLite 的地方；其他模块拿到的是对象和事件，不拿 db 句柄。
- 模型调用只经内核（`lines/`、`kernel/`）发出；设备和界面不调模型。

## 数据与状态（《从零方案》《架构方案》落到代码上）

- SQLite 里的现有记录是资产，一条不丢：数据迁进新库 `plasticine.sqlite`，迁移脚本只读旧库、写新库，带校验（行数、抽样对比、用户确认字段一条不少），迁移前快照。新库的迁移只加不改旧迁移；要删表、删列时新开一条 `destructive` 迁移（0059 起允许，见
  `state/migrations/migrate.ts`），发布时部署脚本先在线备份数据库。
- 每类对象（约定、记忆条目、笔记、项目与待办、线……）各一张表、各一个 schema。
- 来源权重 `w` 是字段（1 / 0.5 / 0.1），只表示来源，代码里不许拿它当真值或权限判断；唯一允许的用法是上下文超预算时的截断顺序（先截低 w），截掉了什么记进这一轮的「它做了什么」（10-26 第 19 条）。
- 用户原话和系统处理必须分别留真实来源；不能伪造设备签名、替用户补写答案，或把推测改成现实结果。系统可依明确委托退役过时提议、内化工作规则和自主发布（第 99 条）；p 和现实结果仍保留原确认语义。
- 每个有副作用的动作带稳定的动作标识，重放不重复执行（`system/` 的 external-once 和 receipts）。
- 线的状态只经 `LineKernel` 改；非法的转换抛错不静默。

## 安全（用户的硬规矩，代码里也一样）

- 密码、密钥、令牌不进代码、不进日志、不进聊天记录、不进提交；只从服务器上的环境或密钥文件读。
- 删除按实际用户授权执行并留回执；已有明确清理范围不重复要求用户再点卡或输入名字。当前业务原文和来源保留；旧迁移备份按第 99 条核验后清理。
- 安全检查或分类器拦下的操作不绕过，停下来告诉用户。
- 截图、命令和 SSH 输出里看到的卡号、邮箱不复述；含聊天或记忆内容的临时文件用完覆盖。

## 每次改动的流程

1. 读现状：相关模块的 `index.ts`、schema、已有测试；写下这次改动的范围和不动的东西。
2. 先写测试：失败的测试先存在。
3. 实现到测试过；跑全测、typecheck、lint（行宽与文件长度是 lint 规则）。
4. 界面改动装成客户端截电脑 1440×900 和手机 390×844（`scripts/browser/`），自己看过再请维护者确认。
5. 记录：目标、改了哪些文件、测试结果、截图位置、还没做的。发布走安装包流程（`docs/install-packages.md`）。
6. 提交粒度一个关注点一次；提交信息中文一句话 + 影响范围，不写"修复若干问题"。
7. **Claude 的开发**（第 57、97、98 条）：遵守本次用户指定的工作树与操作范围；获准推送时按现有流程跑全测和扫描，不再跑 Codex 审阅。格式建议只提醒，空 catch 和类型错误仍须修好。

审查用 [review-checklist.md](references/review-checklist.md)，测试怎么写用 [testing.md](references/testing.md)。在 Plasticine 内部，技能用 `skills_search` 找、`skill_read` 读正文和参考。
