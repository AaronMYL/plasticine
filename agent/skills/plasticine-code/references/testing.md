# 测试规范

## 核心原则

- **先写测试再实现**：每个新功能和 bug 修复都必须附带测试；修 bug 先写可复现的失败测试。
- **按行为组织**：测试按模块与行为放置在 `agent/tests/<module>/` 或 `client/tests/<layer>/`，不要求与源文件一一对应；测试文件不得放在 `client/src/`。
- **全英文测试标题**：所有 `test()` / `it()` / `describe()` 标题及条件 `skip:` 原因必须使用简洁清晰的英文描述行为（`no-cjk-test-title` 强制检查）；断言的产品 UI 文案保留中文。
- **测行为不测实现**：断言状态变化、输出和副作用回执，不依赖内部调用细节。
- **真实存储 + 隔离外部依赖**：使用临时 SQLite 跑真实 `state/`；不联网、不调真实模型，外部服务与模型均使用仓库内的假实现（`startTestApp`、`scriptedText`、`client/src/api/fake/`）。
- **无残留与确定性**：测试数据使用工厂函数构造（仅用虚构数据）；测试结束后清理临时文件与定时器；时间使用假时钟 `testClock()`。
- **禁止无条件跳过**：禁用 `.skip`、`.only`、`.todo`；环境依赖跳过必须写英文条件原因（`{ skip: hasTool ? false : 'tool not installed' }`）。

## 必测范围

| 模块 | 覆盖重点 |
|---|---|
| `state/` | 对象增改查、版本冲突保护、新迁移在旧库演练 |
| `app/` | 401/400/200 路径、幂等请求重放、回执未知时返回待核实 |
| `lines/`、`kernel/` | 排队/插队/叫停、硬线拦截、重试与重启续跑、凭据不泄露 |
| 业务包 | 规则正反路径、schema 校验拒绝、旁路模型异常处理 |
| `system/`、`devices/`、`cloud-tools/` | 幂等回执、备份恢复、超时/断线/超限保护 |
| `client/` | 加载/空/正常/出错/离线状态、待核实回执、401 登录跳转 |

## 规范自动检查

所有能自动化的代码与界面规范均写入 `npm run check`；确有合理例外的单行使用 `/* allow-exception: <reason> */` 或 `// allow-exception: <reason>` 标注。

## 验收与测试分离

单元测试通过仅代表代码按预期运行；界面改动仍需通过 `scripts/browser/` 截取桌面（1440×900）和手机（390×844）视图自查，并在汇报中分开说明测试结果、截图检查和真实行为验证。
