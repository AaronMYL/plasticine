# 测试怎么写

## 原则

- **每个新功能、每个修掉的问题都有测试**：先写失败的测试，再写实现。修问题时，先写一条能重现它的测试。
- **测试按行为放，不按源文件一一对应**：一个行为一条测试，放在它测的那个模块名下（`agent/tests/<模块>/`、
  `client/tests/<层>/…`）。一条测试跨了几个文件没关系；一个源文件没有同名测试文件也没关系，只要它的行为有测试管着。
  界面的测试都放 `client/tests/`，不放在 `src/` 里。
- 测试描述用中文写行为：「离开 5 小时回来，接上了之前的话」，不写 "renders header"。
- 测行为不测实现：断言状态、输出、副作用的回执，不断言内部调用次数（幂等回执除外，那正是要测的）。
- 存储用真的：拿临时 SQLite 跑真实的 `state/`（`memoryState()` 或 `startTestApp()`），不给 `state/` 写假实现。
- 测试不碰网络、不碰真实模型：线用 pi-ai 的 faux 提供商（`agent/tests/app/helpers.ts` 的 `startTestApp(steps)`），旁路调用用
  `agent/tests/tools/helpers.ts` 的 `scriptedText`，都按剧本返回；外部服务（邮件、IMAP、云端浏览器、设备节点）各有一个
  假实现。界面用 `client/tests/helpers.tsx` 的 `renderApp()` 和 `client/src/api/fake/` 的假接口。
- 测试数据用工厂函数造，不复制粘贴大段 JSON；只用虚构的人和事。含中文、长网址、空列表、缺图这类边界各一条。
- 测试跑完不留文件、不留定时器；时间用假时钟（`testClock()`），不靠真的等。
- **不许无条件跳过**：没有 `.skip`、`.only`、`.todo`。只在某种系统、装了某个工具才能跑的，写成带原因的条件跳过
  （`{ skip: 条件 ? false : '原因' }`）：报告里看得见它没跑。

## 哪些一定要有测试

| 范围 | 要测的 |
|---|---|
| `state/` | 每类对象的增改查；版本冲突报错不覆盖；新迁移在旧库上跑通（`scripts/rehearse-migrations.ts`） |
| `app/` | 每个资源的 401 / 400 / 200；带请求标识的写操作重放不重做；回执不确定时客户端拿到「结果待核实」 |
| `lines/`、`kernel/` | 排队、立即发送、叫停；硬线工具先问；失败重试、额度暂停、重启续跑；凭证不出库 |
| 业务包 | 每条规则的正反两面；给模型的工具参数不过 schema 时拒绝；旁路模型出错（没模型、额度、忙）各有去处 |
| `system/` | 同一动作标识重放不重复执行；备份按时、恢复可核对 |
| `devices/`、`cloud-tools/` | 上限内放行、超限拒绝并报告；超时、断线、对方出错各有说法 |
| 界面 | 一个页面的每种状态（加载、空、有内容、出错、离线）；写操作在路上、待核实、失败各是什么样；切页面后滚动位置和草稿还在 |
| `client/src/api/` | 回执不确定（超时、断网）时是待核实而不是失败；401 触发登录 |

## 规矩本身的测试

规矩能自动检查的都写成了测试，和别的测试一起跑（清单在 SKILL.md 末尾和 plasticine-visual 的 `page-spec.md` 末尾）。
新定一条规矩时，先看能不能加一条这样的检查：读源码、找出违反的地方、报出文件和行号，真有例外的在那一行写「例外：原因」。

## 验收不是测试

测试过了只证明代码按写的在跑。界面改动还要装成客户端截电脑 1440×900 和手机 390×844 的图（`scripts/browser/`），自己逐张
看过；后台的活要有一条真实的线从开到结束的记录。三样分开说：测试过了、截图看了、真实行为验了。
