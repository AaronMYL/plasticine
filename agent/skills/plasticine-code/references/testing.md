# 测试怎么写

## 原则

- 先写失败的测试，再写实现。测试描述用中文写行为："离开 5 小时回来，今日头部是四句话"，不写 "renders header"。
- 测行为不测实现：断言状态、输出、副作用的回执，不断言内部调用次数（幂等回执除外，那正是要测的）。
- 一个源文件对应一个测试文件，位置同构（`src/state/projects.ts` ↔ `tests/state/projects.test.ts`）。
- 测试数据用工厂函数造，不复制粘贴大段 JSON；含中文、长 URL、空列表、缺图这类边界各一条。
- 测试不碰网络、不碰真实模型：线用 pi-ai 的 faux 提供商（`tests/app/helpers.ts` 的 `respond`），旁路调用用 `tests/brain/helpers.ts` 的
  `scriptedText`，都按脚本返回；外部服务（邮件、IMAP、Claude Docs）各有一个假实现。
- 测试跑完不留文件、不留定时器；用临时 SQLite 文件，结束删除。

## agent 必测

| 模块 | 必须有的测试 |
|---|---|
| state | 每类对象增改查；版本冲突报错不覆盖；迁移脚本在旧库快照上跑通且校验通过；用户确认字段拒绝模型写入 |
| lines / kernel | 排队、立即发送、叫停；硬线工具先问；失败重试、额度暂停、重启续跑；凭证不出库 |
| system | 同一动作标识重放不重复执行；备份按时、恢复可核对；令牌检查器把现有界面整份当新增也过 |
| brain | 工具参数不过 schema 时拒绝；旁路模型出错（没模型、额度、忙）各有去处 |
| attention | 触发条件扫描；四档渠道的分配 |
| devices | 上限内放行、超限拒绝并报告；离线只执行写明范围期限的动作 |
| app | 每个资源的 401 / 400 / 200；回执不确定时客户端能拿到「结果待核实」 |

## client 必测

| 范围 | 必须有的测试 |
|---|---|
| 壳 | 切视图后对话栏滚动位置、草稿、引用片不变；对话栏收起成右下浮动圆球、角标是等你的数、点开后滚动位置和草稿不变；窄于 1024 对话栏自动收成圆球，点开浮在主区上；侧栏手动收起 / 展开，窄于 1280 自动收成 64px 图标条，悬停和键盘聚焦都浮出文字；浮层打开时：遮罩只在主区，侧栏和对话栏没被盖，面板没有 `aria-modal`，焦点移入面板，Tab 能走到对话栏并能输入发送，Esc 关闭后焦点回到入口，对话栏收起时圆球在 Sheet 之上且能点开；记录整页自动收起对话栏、不显示圆球；页头每页都有铃和头像 |
| 七个原语 | 每个原语每种状态渲染一条；要你定卡一次只摊开一张、点选项变成用户消息且卡收成一行；小签按类型描边（授权 / 动手用强调色，其余中性），同一张卡在对话和任务清单「等你」区样式一致；等你区按动手 > 授权 > 确认 > 定排；任务条勾过收到「今天」；就地编辑失败不丢草稿 |
| 今日 | 没离开过是日期 + 等你 n；离开超阈值是四句话 + 「接上了 / 没接上」两个按钮；五个小块点开到对应页；十件事看过计数 |
| 对话 | 流式中新消息不改变当前可见段落；预测一句灰字 Tab 采用、打字消失；「它做了什么」点开才请求 |
| api | 回执不确定（超时、断网）时状态为待核实而不是失败；401 触发登录事件 |
| 遥测 | 每个采数事件点存在且开关关闭时不发 |

## 验收不是测试

单元测试过了只证明代码按写的在跑。界面改动还要装成客户端的电脑和手机截图（电脑 1440×900、手机 390×844，`scripts/browser/` 装成客户端截）；后台活要一条
真实的线从开到结束的记录。三样分开报告：测试过了、截图看了、真实行为验了。
