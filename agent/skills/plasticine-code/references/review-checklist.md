# 审查清单（提交前自查，审别人的改动也用这张）

逐条打勾。任何一条打不上，改动不算完成；写明是哪条、为什么这次例外、谁批的。

## 形

- [ ] 没有一行超过 120 个字符；没有一行多个语句。
- [ ] 新文件只有一个职责；源码超过 500 行的（lint 提醒）看过确实只有一个职责，测试文件不限长度。
- [ ] 文件在正确的模块目录里；没有跨目录引内部文件。
- [ ] 没有 `any`；外部输入过了 schema。
- [ ] 没有空的 `catch {}`；每个 catch 要么处理、要么带上下文抛、要么写日志并把状态置为待核实。
- [ ] 没有魔法数；常量写了来由。
- [ ] 标识符英文、文案中文、注释说为什么。

## 测

- [ ] 先有失败的测试，再有实现（提交历史能看出来，或说明里写了）。
- [ ] agent 和 client 的改动都有对应测试；client 没有测试的改动不收。
- [ ] 全测、typecheck、lint 都过；没有被跳过（skip）的测试。
- [ ] 界面改动有装成客户端的电脑和手机截图。

## 对

- [ ] 接口 schema 在 `shared/`，client 从那里导。
- [ ] 来源权重 w 只当来源，没被当真值或权限。
- [ ] 用户确认字段只接受带用户设备确认的请求。
- [ ] 有副作用的动作带稳定动作标识；重放不重复。
- [ ] 界面沿用七个原语和方向 I 令牌（一底一前景、没有卡片阴影、强调色只做点和描边且 ≤ 2%、不用玻璃、不放插画）；确需扩展时留有设计依据。

## 安

- [ ] 没有密钥、令牌、密码出现在代码、测试、日志、提交信息里。
- [ ] 没碰受保护路径；碰了就标「要你确认」。
- [ ] 没有删除数据、分支、服务、定时任务的操作，除非用户明确要求。
- [ ] 新依赖写了为什么非加不可。

## 说

- [ ] 提交信息：中文一句话 + 影响范围。
- [ ] 改动记录写了：目标、文件、测试结果、截图位置、没做的。
- [ ] 测试过了、截图看了、真实行为验了，三样分开说，没有互相代替。
